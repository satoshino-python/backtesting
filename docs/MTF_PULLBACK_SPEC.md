# 上位足押し目 × 下位足転換 戦略 実装仕様書

## 1. 目的

裁量で行っている次のトレード手法を、ルール化してバックテストできる形にする。

> 上位足が上昇トレンド（高値・安値の切り上げ）の中で、上位足のサポートゾーンまで押してきた。
> そこで下位足の下降構造（高値・安値の切り下げ）が崩れ、その後に下位足のロールリバーサル水準まで押してきた。
> この局面で、何らかのトリガーを確認してロングエントリーする。

- 対象はまずロングのみとする。ショートは高値と安値を反転させて対称に作る（後述のタスク）
- 参照実装：`mtf_pullback_strategy.py`（本仕様に沿って作成・動作確認済みの雛形）

---

## 2. 時間足の組み合わせ

| 役割 | 例 |
|---|---|
| 上位足 | 週足 / 日足 / 4時間足 |
| 下位足 | 4時間足 / 1時間足 |

- 入力データは**下位足のみ**とし、上位足は下位足をリサンプリングして作る（データの整合性を保つため）
- 組み合わせはパラメータ `htf_rule`（例：`"4h"`, `"1D"`）で切り替える

---

## 3. ルールの定義

### 3.1 スイング（高値・安値）の判定

- フラクタル方式を使う。左右 n 本より高い足をスイング高値、左右 n 本より安い足をスイング安値とする
- **同じ価格が並んだ場合は、最初の1本だけをスイングとして扱う**（二重カウントを防ぐ）
  - 高値：`左n本の最大値 < 当該高値` かつ `当該高値 >= 右n本の最大値`
  - 安値も同様に判定する
- **スイングが確定するのは n 本後**とする。確定前のスイングをシグナル判定に使ってはならない（未来参照の防止）

### 3.2 上位足の条件（上位足図）

```
            ／＼
     ／＼  ／    ＼  ← 押し
────／──＼／──────●───  ← 抜けた前回高値 = サポートゾーン
  ／
```

- **上昇トレンド**：確定済みの直近2つのスイング高値が切り上がり、かつ直近2つのスイング安値も切り上がっている
- **サポートゾーン**：
  - デフォルト（`support_mode="broken_high"`）：上抜けされた前回のスイング高値（ロールリバーサル）
  - 代替（`support_mode="last_low"`）：直近の押し安値
  - ゾーンは水準 ± 上位足ATR × `htf_zone_atr` の帯とする（安値が線を少し割り込むケースを拾うため）
- **目標値**：上位足の直近スイング高値（利確の代替に使う）
- 上位足の情報は、**その上位足が確定した時刻以降の下位足にだけ**割り当てる（4時間足の途中で判定しない）

### 3.3 下位足の条件（下位足図）

```
 ＼  H_a
   ＼／＼   H_b（赤線 = 2個前の高値）
       ＼／＼        ／＼
──────────＼──H_c──／────＼──／   ← H_b水準まで押す（緑丸）→ トリガーでエントリー
            ＼／＼／        ＼／
             底   押し安値(HL)
━━━━━━━━━━━━━━━━━━━━━━━━━━━  ← 上位足サポートゾーン（オレンジ線）
```

用語：

| 記号 | 意味 |
|---|---|
| 底 | 上位足ゾーン内でつけた押しの最安値（オレンジ線） |
| H_b | **底より前**にできた最後の戻り高値（赤線）。ロールリバーサル水準になる |
| H_c | 底の後にできた小さな高値。**転換判定の対象外** |
| HL | 底の後にできた押し安値。否定条件に使う |

**注意**：「最後の高値」とは底より前の戻り高値（H_b）のことであり、底の後の H_c ではない。H_c の上抜けを転換と判定してはならない。

## 4. 状態遷移（シグナル判定の流れ）

下位足を1本ずつ進めながら、次の状態を順に遷移させる。

```
IDLE → WAIT_CHOCH → WAIT_RR → WAIT_TRIGGER → エントリー → IDLE
          ↓            ↓            ↓
        取り消し     取り消し      取り消し  → IDLE
```

### ① IDLE（待機）
- 開始条件：上位足が上昇トレンドで、下位足の安値が上位足ゾーン上限以下、かつ終値がゾーン下限以上
- 記録する値：開始位置、押しの最安値（底）とその位置、ゾーン下限、上位足の目標値

### ② WAIT_CHOCH（下降構造の崩れ待ち）
- 安値を更新したら、底の値と位置を更新する
- 転換条件（CHoCH）：
  - 底より前にできた確定済みスイング高値のうち、直近2つが切り下がっている（H_a > H_b）
  - 終値が H_b を上抜けた
- 転換したら：
  - ロールリバーサル水準 `rr = H_b`
  - 否定ライン `inval` = 底の後にできた確定済みスイング安値（HL）。まだ無ければ底
- 取り消し：終値がゾーン下限を割る、または `setup_expiry` 本を超える

### ③ WAIT_RR（ロールリバーサル水準への押し待ち）
- まず、価格が一度上へ離れるのを待つ：高値 ≥ `rr` + ATR × `rr_away_atr`
  （転換直後の足で即座に「戻ってきた」と判定しないため）
- 離れた後、安値 ≤ `rr` + ATR × `rr_zone_atr` になったら接触とみなし、③の接触安値を記録する
- **割り込む深さの制限は設けない**（ユーザー確認済み）。否定されるのは `inval` を割ったときだけ
- 取り消し：終値が `inval` を割る、または `setup_expiry` 本を超える

### ④ WAIT_TRIGGER（トリガー待ち）
- 接触安値を随時更新する
- トリガー：終値が直近 `trigger_n` 本の高値を上抜けた
- エントリー：**次の足の始値**で成行買い
- 取り消し：終値が `inval` を割る、または `setup_expiry` 本を超える
- 将来、トリガーを差し替えられる設計にする（モメンタム指標など。後述のタスク）

## 5. 決済ルール

| 項目 | ルール |
|---|---|
| 損切り | 接触安値 − ATR × `sl_buffer_atr` |
| 利確 | エントリー + 損切り幅 × `rr_target`（`rr_target=None` なら上位足の目標値） |
| 同じ足で損切りと利確の両方に触れた場合 | **損切りを優先**（保守的判定） |
| 保有中 | 新しいシグナルは出さない（ポジションは1つのみ） |

## 6. パラメータ一覧

| パラメータ | 既定値 | 内容 |
|---|---|---|
| `htf_rule` | `"4h"` | 上位足の時間軸 |
| `swing_n_htf` | 3 | 上位足スイング判定の左右本数 |
| `swing_n_ltf` | 3 | 下位足スイング判定の左右本数 |
| `atr_len` | 14 | ATRの期間 |
| `support_mode` | `"broken_high"` | 上位足サポートの種類 |
| `htf_zone_atr` | 0.5 | 上位足ゾーン幅（上位足ATR倍） |
| `rr_away_atr` | 1.0 | 転換後にRR水準から離れる幅（下位足ATR倍） |
| `rr_zone_atr` | 0.3 | RR水準への接触判定幅（下位足ATR倍） |
| `trigger_n` | 5 | トリガーの直近高値の本数 |
| `setup_expiry` | 72 | 各段階の有効期限（下位足本数） |
| `sl_buffer_atr` | 0.2 | 損切りの余裕幅（ATR倍） |
| `rr_target` | 2.0 | 利確のR倍数 |

## 7. 出力

### トレード一覧（1トレード1行）
`entry_time`, `entry`, `sl`, `tp`, `exit`, `exit_pos`, `R`, `rr_level`, `swing_low`

### 集計
トレード数、勝率、平均R、合計R、最大ドローダウン（R）、プロフィットファクター

## 8. 実装上の必須事項（未来参照の防止）

1. スイングは確定後（n本後）にのみ使う
2. 上位足の状態は、その上位足の確定時刻以降にだけ参照する
3. シグナルは足の確定（終値）で判定し、エントリーは次の足の始値とする
4. 同一足内の損切り・利確の順序が不明な場合は損切り優先

---

## 9. 動作確認テスト

### 9.1 パターン再現テスト（必須）
下位足図の折れ線をそのまま価格データに変換し、上位足条件を固定（上昇中・底付近がゾーン）して実行する。

- 折れ線の価格（図のy座標を `600 - y` で変換）：
  `542, 328, 442, 190, 313, 62, 265, 170, 445, 257, 525, 500, 560`（各区間10本で線形補間）
- 期待結果：
  - トレードが1件発生する
  - `rr_level` が H_b（313付近）になる。H_c（265）を選んでいたら不合格
  - エントリーは緑丸の押し（257付近）の後
  - 損切りは緑丸の安値の少し下

### 9.2 実行確認
ランダムウォークの人工データでエラーなく最後まで動くこと（成績は評価しない）。

## 10. 今後の実装タスク

1. **データ読み込み**：証券会社のCSVの列名に合わせて `load_csv` を調整する（想定列：datetime, open, high, low, close）
2. **エントリー地点の可視化**：ローソク足チャート上に、底・H_b（RR水準）・接触点・エントリー・損切り・利確を描画する。成績を見る前に、**検出結果が目視のセットアップと一致しているか**を確認する
3. **トリガーの差し替え**：直近N本高値抜けに加え、モメンタム指標（RSIの50上抜け、MACDなど）を選べるようにする
4. **ショート側の追加**：高値と安値を反転させた対称ロジック
5. **検証方法**：パラメータは少数に絞り、期間を分割したウォークフォワード検証で過剰最適化を避ける
6. **実行環境**：GitHub非公開リポジトリに配置し、Claude Code on the web からスマホでも実行できるようにする
