# スイングブレイクアウト・トレンドフォロー戦略 バックテスト仕様書

元の仕様書（`breakout_strategy_spec.md`）を、このリポジトリにあるデータと既存の仕組み（GMOクリック証券の1分足、
NY 17:00 区切りの4時間足、データから求めるスプレッド）に合わせて書き直したもの。
元の仕様から変えた点・決めていなかった点を補った箇所は **［補足］** と書いた。

- 実装: `breakout_trend.py`（指標・売買シミュレーション・集計）、`breakout_trend_run.py`（全ペアの検証・感度分析・ウォークフォワード・出力）
- テスト: `python tests/test_breakout_trend.py`（pytest でも可）

## 1. 目的
4時間足のスイングハイ／ローのブレイクに順張りでエントリーし、微損を多く出しつつ大きなトレンドで利益を伸ばす戦略を検証する。

検証したい仮説：「ブレイク後はすぐにブレイク方向へ動き、あまり戻らない」

## 2. 前提
- 時間足：4時間足（**NY 17:00 区切り**。17-21 / 21-1 / 1-5 / 5-9 / 9-13 / 13-17 時の6本/日。既存スクリプトと同じ）
- 対象：FX 5ペア（AUDUSD / EURUSD / GBPUSD / USDCHF / USDJPY）と株価指数CFD（SP500 = GMOクリック証券の US500）
  - ［補足］先物の価格データはリポジトリに無い。SP500（US500 CFD）を先物の代わりに扱う（8章の注意を参照）。
- 保有期間の想定：数日〜最長2週間
- 実装言語：Python（pandas / numpy、グラフは matplotlib）
- 1銘柄につき同時保有は1ポジションまで。保有中の新規シグナルは無視する
- 売買判定と約定は4時間足だけで行う（1分足は使わない）。足の中の値動きの順番が分からない場面は、7章の保守的な扱いで決める。

## 3. 入力データ
- ［変更］CSV ではなく、既存の GMOクリック証券 1分足（BID/ASK、月ごとの ZIP。`histData/<ペア>/`）を使う。
  - 読み込みは `main_4H_fixedSL.load_gmo_click_1min_data()`。日本時間の記録を **NY時間に変換**する（サマータイムは自動）。
  - 価格は仲値 `(BID+ASK)/2`。
  - 4時間足は `main_4H_fixedSL.resample_to_signal_bars(df, 17, 4)` で作る。
- datetime はバーの開始時刻（NY 現地時刻、タイムゾーンなし）
- 欠損バー・週末ギャップはそのまま扱う（補間しない）。出来高は無い。
- データの期間: FX は 2020-01〜2025-12、SP500 は 2024-01〜2025-12。
- ［補足］検証期間は既存の検証と揃えて **2021-01-01〜2025-12-31**（取引日。SP500 はデータのある 2024-01〜）。
  開始月の1ヶ月前から読み込み、ATR とスイングの助走に使う（助走期間にはエントリーしない）。

## 4. 指標
- **ATR**：ATR(14)。Wilder方式（`dow_trend.atr_wilder()` を使う。既存の `main_4H_*` の EMA 方式の ATR とは違う）
- **スイングハイ**：あるバーの高値が、左右それぞれ3本のバーの高値より高いもの（フラクタル）
- **スイングロー**：あるバーの安値が、左右それぞれ3本のバーの安値より低いもの
- ［補足］「より高い／低い」は**厳密**に判定する（同値は不採用。`dow_trend.py` と同じ。既存の `main_4H_*` は同値を含む）。

### ⚠ 先読み禁止
スイングは右側3本が確定するまで認識できない。バー i のスイングは、バー i+3 の確定後に初めて「既知」として扱うこと。
ATR もバー t の確定時点の値（バー t までのデータだけで計算した値）を使う。

## 5. エントリールール
### 買い
1. 直近の「確定済み」スイングハイを基準価格とする
2. 4時間足の**終値**がその基準価格を上抜けたバー（前バー終値 ≦ 基準価格 < 当バー終値）をシグナル足とする
3. 次の足の**始値**で成行買い
4. 一度ブレイクに使ったスイングハイは再利用しない
   - ［補足］スイングは**最初に終値で上抜けた時点で使用済み**になる。保有中・決済した足などでエントリーしなかった場合も同じ
     （同じスイングを後から再び上抜けてもエントリーしない）。次のスイングハイが確定するまで買いシグナルは出ない。
   - ［補足］新しいスイングハイが確定すると、古いスイングハイ（未使用でも）は基準価格ではなくなる。

### 売り
上記の逆（直近確定スイングローを終値で下抜け → 次足始値で売り）

- ［補足］ATR がまだ計算できない足（データ先頭の14本未満）と、検証期間外の足のシグナルではエントリーしない。

## 6. 決済ルール（買いの場合。売りは上下逆）
ATR値は**シグナル足確定時のATRで固定**する（パラメータ `atr_mode="fixed"`。`"update"` で「毎バー更新」に切り替え）。
- ［補足］`"update"` のとき、初期損切りと 1R はシグナル足の ATR のまま。時間切れ到達基準・建値移動・トレイル幅に、各バーの確定時の ATR を使う。
- ［補足］エントリー価格・決済価格はコスト（8章）込みの約定価格。以下の水準はすべて約定価格（エントリー価格）から測る。

### 6-1. 初期損切り
- ストップ = エントリー価格 − 1.5 × ATR
- 1R = 1.5 × ATR（当初リスク）

### 6-2. 時間切れ撤退
- エントリー足を1本目として6本目の終値時点で、エントリー後の最高値がエントリー価格 + 1.0 × ATR に一度も達していなければ、次の足の始値で決済

### 6-3. 建値移動
- エントリー後の最高値がエントリー価格 + 1.5 × ATR（= +1R）に達したら、ストップを建値（エントリー価格）へ移動

### 6-4. トレイリングストップ（建値移動後に開始）
次の2つのうち、**価格に近い方（=高い方）**をストップとする：
- A：エントリー後の最高値 − 2.0 × ATR
- B：エントリー後に確定した直近スイングローの安値

ストップは**有利な方向にしか動かさない**（下げない）。
- ［補足］建値移動の条件を満たした足の確定時から、ストップ = max(現在のストップ, 建値, A, B) で更新する。
- ［補足］B は「エントリー足以降の足で確定した」スイングロー（確定 = ピボットの3本後）。無ければ A だけ。

### 6-5. 最大保有期間
- エントリーから60本経過したら、次の足の始値で決済（エントリー足を1本目として60本目の終値で判定）

## 7. 約定・処理順のルール
- ストップ更新はバー確定後に計算し、**次のバーから**有効にする
- ストップ判定はバーの高値・安値で行う（仲値。［補足］BID/ASK の差はコストとして別に引く）
- 窓開け（ギャップ）でストップを越えて始まった場合は、そのバーの始値で約定
- 同一バー内で「建値移動の条件達成」と「ストップ到達」が両方起きた場合は、**保守的にストップ到達を先**とみなす
- 決済したバーで新たなシグナルが出ても、エントリーは次のシグナルを待つ
- ［補足］1本の足の処理順: ①予約した決済（時間切れ・最大保有）を始値で実行 → ②予約したエントリーを始値で実行
  → ③ストップ判定（エントリー足も対象）→ ④足の確定後に最高値・建値移動・トレイル・時間切れ・最大保有を判定
  → ⑤スイングの確定とシグナル判定。
- ［補足］検証期間の最後の足でまだ保有していれば、その足の終値で決済する（決済理由「期末」）。
- ［補足］MFE / MAE はエントリー後の最高値・最安値から測る（ATR はシグナル足の値）。ストップで決済した足は、
  「ストップが先」とみなすので有利側の値は含めず、不利側は約定価格までとする。始値で決済した足は始値だけを含める。

## 8. コスト
- 銘柄ごとにスプレッド（価格単位）とスリッページ（価格単位）をパラメータで設定
- エントリー・決済の両方に適用
- ［補足］スプレッドの既定値は、データの検証期間の平均スプレッド（ASK−BID の平均。`load_gmo_click_1min_data()` の
  平均相対スプレッド × 平均仲値で価格単位にする）。仲値で売買するので、**1回の約定ごとにスプレッドの半分 + スリッページ**を
  不利な方向に乗せる（往復でスプレッド1回分 + スリッページ2回分。既存スクリプトと同じ考え方）。スリッページの既定は 0。
- ［補足］コスト2倍の検証は、スプレッドとスリッページの両方を2倍にする。
- 先物はロールオーバーの影響に注意（つなぎ足の調整方法を明記すること）
  - ［補足］SP500（US500 CFD）は GMOクリック証券の価格をそのまま使い、**つなぎ足の調整はしない**。限月が変わる日に
    価格の段差が残っていれば、それもそのまま値動きとして扱う（ブレイクやストップの判定に影響しうる）。
    CFD の価格調整額・金利調整額、FX のスワップも損益に含めない。

## 9. ポジションサイズ
- 1トレードのリスク = 口座資金の 1%（パラメータ化、0.5〜1%）
- 数量 = リスク金額 ÷ (1.5 × ATR × 1単位あたりの価値)
- 基本の評価は R 単位で行い、資金曲線は固定％リスクで別途算出
- ［補足］資金曲線は「エントリー時点の確定済み資金 × 1%」をリスク額とし、決済時に R × リスク額を加える（複利）。
  全銘柄合算の曲線は1つの口座で全銘柄を同時に持つ扱い。1単位あたりの価値は既定 1（決済通貨建て）。
  R で評価するので、為替換算はしない。

## 10. 出力
結果は実行ごとに `breakout_results/<日時>_<ラベル>/` に保存する（前の結果を上書きしない）。

### トレード一覧（CSV）
銘柄、方向、エントリー日時・価格、決済日時・価格、決済理由（初期損切り／時間切れ／建値／トレイル／最大保有［補足: ／期末］）、
保有本数、損益（価格・R）、MFE（ATR単位）、MAE（ATR単位）
- ［補足］決済理由の「建値」は、ストップがちょうど建値のときに決済されたもの。建値より有利な位置へ動いた後は「トレイル」。
- ［補足］日時は NY 現地時刻。ストップで決済した場合は、その足の開始時刻を決済日時とする。

### 集計
- トレード数、勝率、平均利益（R）、平均損失（R）、ペイオフレシオ
- 期待値（R/トレード）、プロフィットファクター
- 最大ドローダウン、最大連敗数（［補足］最大DDは R の累積と、固定％リスクの資金曲線の % の両方）
- 決済理由別の件数と平均損益
- 銘柄別・年別の成績

### グラフ
- 資金曲線（全体・銘柄別）
- R分布のヒストグラム
- MFE分布のヒストグラム（「+3ATRに達したトレードのうち何％が+6ATRに達したか」も表示）
- MAE分布（仮説「戻ってこない」の検証用）
- ［補足］このリポジトリの決まり（CLAUDE.md）に従い、ペアごとのトレード付きダウ理論チャート（`dow_swing_chart.make_chart()`）も出力する。

## 12. 検証の手順
1. まず初期値のみで全期間を検証
2. パラメータを1つずつ変えて感度を確認（成績が特定の値だけで良い場合は過剰最適化を疑う）
3. ウォークフォワード：期間前半でパラメータを決め、後半（未使用データ）で成績が崩れないか確認
   - ［補足］前半 = 2021-01〜2023-12、後半 = 2024-01〜2025-12（`trend_quality_study.py` と同じ分け方）。
     手順2の各パラメータについて、前半の全ペア合計の期待値（R/トレード）が最も高い値を選び、それらを組み合わせた設定を作る。
     組み合わせた設定と初期値を、前半・後半それぞれで比べる。期間はエントリー日で分ける（実行は全期間で1回）。
   - ［補足］SP500 は前半のデータが無いので、後半にだけ含まれる。
4. コストを2倍にしても期待値がプラスか確認
